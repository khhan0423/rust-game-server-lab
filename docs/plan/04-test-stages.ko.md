# 테스트 단계: 개발부터 출시까지

[English](04-test-stages.md) | **한국어**

- 상태: **논의용 초안** (2026-11-20). 2026-11-20에 정한 것: 게스트 로그인은 알파까지 쓰고 정식 게임에서는 쓰지 않는다. 스팀 등록은 베타가 가까워질 때까지 미룬다. 지인 테스트 서버는 AWS에서 돌린다.
- 관련: [실행 계획](README.ko.md), [파일럿](01-pilot.ko.md), `docs/design/07-login-account.ko.md`, `docs/research/guest-account-recovery.ko.md`

게임이 개발자 PC에서 돈을 내는 유저에게 가기까지를 단계별로 따라가 보고, 단계마다 서버가 무엇을 갖춰야 하는지 적는다.

## 단계

| 단계 | 누가 하나 | 어떻게 들어오나 | 로그인 | 유저 데이터 | 결제 |
|---|---|---|---|---|---|
| 개발 | 개발자 | 개발 PC | 게스트 | 언제든 지움 | 없음 |
| 지인 테스트 | 초대한 지인, 몇 명에서 수십 명 | 직접 전달한 클라이언트, 초대 코드, 테스트 서버 주소 | 게스트 | 테스트가 끝나면 지움 | 없음 |
| 알파 | 초대한 유저, 수십에서 수백 명 | 직접 전달한 클라이언트, 초대 코드, 테스트 서버 주소 | 게스트 | 알파가 끝나면 지움 | 없음 |
| 베타 | 신청한 더 큰 집단 | Steam Playtest 신청. 여러 차례로 나눠 연다 | 스팀 | 출시 전에 지움 | 실제 돈은 없음. 결제 흐름은 스팀의 샌드박스에서 시험 |
| 출시 | 게임을 가진 누구나 | 스팀 상점. 얼리 액세스 또는 정식 출시 | 스팀 | 유지 | 실제 |

스팀 문서가 Steam Playtest에 대해 말하는 내용은 다음과 같다(2026-11-20 확인, [출처](https://partner.steamgames.com/doc/features/playtest)). 본 게임에 딸린 별도의 앱이고, 본 게임과 같은 Steamworks 기술 기능을 쓸 수 있으며, 누구를 들일지 개발자가 정하고 언제든 끌 수 있다. 무료이고, 게임 내 결제로 돈을 벌거나 접근권을 팔면 안 된다. 만드는 중인 게임에 돈을 받으려면 Steam 얼리 액세스를 써야 한다. 플레이테스트 빌드는 스팀으로 실행하므로 그 안에서 스팀 로그인이 동작한다.

스팀 로그인에는 비용과 준비 기간이 든다. 플레이테스트 앱은 본 게임의 앱에서 만들기 때문에 먼저 게임을 스팀에 등록해야 하고, 등록비는 앱 하나에 100달러다. 환불되지 않지만 게임이 1,000달러를 벌면 돌려받는다([출처](https://partner.steamgames.com/doc/gettingstarted/appfee)). 서버는 그 앱에 묶인 Web API 키로 유저의 스팀 티켓을 확인한다([출처](https://partner.steamgames.com/doc/features/auth)). 그래서 등록 없이 실제 스팀 로그인을 시험할 방법은 없다. **확정 (2026-11-20):** 등록비를 미룬다. 이 프로젝트는 실험이고 알파는 초대한 사람만 들어오므로, 알파는 게스트 로그인과 초대 코드로 규모가 큰 지인 테스트처럼 치른다. 게임을 내놓기로 마음을 정하면 그때 스팀에 등록하고, 스팀 로그인은 베타에서 시작한다. 미루는 대가는 스팀 연동의 문제를 늦게 보게 된다는 것이다. 그래서 등록과 베타 사이에 연동을 시험할 시간을 일정에 둔다.

## 단계마다의 목적

**지인 테스트.** 서버가 처음으로 인터넷을 건너 실제 사람들과 도는 때다. 로그인, 함께 돌아다니기, 재접속이 PC 한 대 밖에서도 버티는지 확인하고, 어색한 점을 듣는 것이 목적이다. 작고 격식 없이 한다. 계정은 게스트 계정이고 유지하지 않는다.

**알파.** 지인 테스트와 같은 구성에 사람과 게임 내용이 더 많다. 모르는 사람들이 들어와도 전체 경로가 도는지 확인하는 것이 목적이다. 닉네임과 유저 태그, 친구, 샤드가 섞인 파티가 여기에 든다. 컨텐츠는 얇다. 데이터는 끝나면 버리고, 이 점을 시작 전에 알린다.

**베타.** 스팀을 통한 첫 테스트이자 부하와 운영의 예행연습이다. 여기서 스팀 로그인이 게스트 로그인을 대신한다. 출시 때 예상하는 인원에 가까운 규모로 돌리면서 운영 도구, 감시, 점검, 플레이 도중의 계획된 서버 강제 종료를 해 보는 것이 목적이다. 결제 흐름은 실제 돈이 움직이지 않는 스팀 샌드박스에서 돌려 본다.

**출시.** 여기서부터 데이터를 유지한다. 얼리 액세스로 시작하면 서버 입장에서는 그것이 출시다.

## 이를 위해 서버에 필요한 것

- **설정의 환경 이름** (개발, 지인 테스트, 알파, 베타, 라이브). 환경마다 데이터베이스, 키, 주소가 따로다. 로그인 토큰과 티켓에 환경 이름을 넣어, 테스트에서 발급한 것을 라이브가 거절하게 한다.
- **게스트 수단 스위치.** 개발, 지인 테스트, 알파에서 켠다. 베타나 라이브로 설정된 서버는 게스트 수단이 켜져 있으면 기동을 거부한다.
- **지인 테스트와 알파용 초대 코드.** 게스트 계정을 만들려면 개발자가 나눠 준 코드가 있어야 한다. 코드는 정해진 횟수만큼 쓸 수 있다. 이것이 없으면 서버 주소를 아는 누구나 계정을 만들 수 있다.
- **계정 생성 제한.** 실수나 공격으로 데이터베이스가 계정으로 가득 차지 않게 한다.
- **입장 시 버전 확인.** 옛 빌드를 쓰는 테스터가 이상한 오류 대신 "업데이트해 주세요"를 분명히 보게 한다.
- **초기화 절차.** 문서로 적고 연습해 둔다. 입장을 막고, 백업하고, 그 단계의 데이터를 지우고, 깨끗한 상태로 시작한다. 닉네임과 유저 태그는 초기화로 풀린다.
- **초기화 뒤에도 남는 테스터 보상.** 베타 테스터에게 출시 때 무언가를 주기로 했다면, 그 약속을 지워지는 데이터 밖에 스팀 ID로 기록해 두었다가 출시 때 일반 지급 경로로 한 번 지급한다. 지인 테스트와 알파의 계정은 스팀 신원이 없는 게스트라서, 이 단계에서 이어 주기로 약속하는 것은 없다.
- **테스터가 문제를 알릴 방법.** 알릴 때 기준으로 유저 태그를 쓴다. 그러면 서버 로그를 그 유저로 검색할 수 있다.
- **지인 테스트 서버를 돌릴 곳.** 포트를 연 개발자 PC이거나, 빌린 작은 Linux 서버다. 서버는 이미 Linux에서 빌드되고 테스트를 통과한다.

## 짚어 둘 위험

- 지인이 저장된 게스트 파일을 잃어 테스트 계정을 잃는다. 지인 테스트에서는 감수하고, 테스터에게 `client-data` 폴더를 보관하라고 알린다.
- 테스트 데이터가 라이브로 새거나, 테스트 빌드가 라이브 서버에 붙는다. 토큰의 환경 이름과 환경별로 따로 둔 키가 이것을 막는다.
- 테스터에게 진행도가 이어진다고 약속하는 것. 계획은 그 반대다. 출시 전의 모든 단계는 초기화로 끝나고, 이름을 붙여 약속한 보상만 이어진다.

## 정할 것

|---|---|

| 지인 테스트 서버를 돌릴 곳 | **확정 (2026-11-20):** AWS의 Linux 서버. 테스트가 가까워지면 소유자가 만든다. 그때까지는 모두 개발 PC에서 돌린다 |
| 단계별 로그인 | **확정 (2026-11-20):** 알파까지는 게스트와 초대 코드. 베타부터는 스팀만 |
| 단계 사이에 데이터를 이어 갈지 | 이어 가지 않는다. 출시 전의 모든 단계가 끝날 때 초기화하고, 이름을 붙여 약속한 보상만 이어 간다 |
| 스팀 로그인을 언제 만들지 | **확정 (2026-11-20):** 게임을 스팀에 등록한 뒤, 베타 전에. 등록은 게임을 내놓기로 정할 때까지 기다린다 |
